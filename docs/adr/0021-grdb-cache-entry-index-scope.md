# GRDB cache entry index follows Android cache semantics

GRDB cache indexing will mirror the Android `DiskCache` model: a generic `cache_entries` table records only `namespace`, `cacheKey`, `createdAt`, and `lastAccessedAt` for cache existence, TTL expiry, LRU eviction, namespace clearing, and key-prefix deletion, while actual cache contents live under `yamibo_cache/<namespace>/<cacheKey>.json` on the file system. TTL is measured from `createdAt` and is not extended by reads; reads only update `lastAccessedAt` for LRU. Cache-specific semantic fields for manga, forum, and novel content are encoded into caller-owned cache keys rather than stored in dedicated semantic index tables, because these transparent caches are regenerable and the database should not become a second source of truth for parsed cache meaning.

# Browsing History Is Display-Only and Separate From Reading Progress

The browsing-history timeline lives in its own `browsing_history` table (one upserted row per content identity: normal thread, novel thread, mode-off manga thread, or mode-on manga directory), carrying only display metadata -- title, board, coarse position text, last-visit time -- capped at 2000 rows and never synced. Resume positions stay in `reading_progress`, including the normal-thread page + floor-anchor records this feature introduces (`.normalThread`'s first writer, restored on every entrance); deleting or trimming history therefore never loses a resume position. This refines rather than reverses ADR-0031's decision to not port Android's `ReadingHistory` table: what 0031 rejected was a history table doubling as the resume-position store, and this table never carries resume state.
